# SITE.md

Reference source: `https://corp.roblox.com/`

Use this file as a reference-only page-structure contract for AI-generated websites.

Pair it with `VOICE.md`: `SITE.md` controls section order and page intent; `VOICE.md` controls copy rhythm, CTA shape, and benchmark gates.

## Site Summary

- Page archetype: **community platform landing**.
- Information density: **balanced**.
- Conversion pressure: **high**.
- Navigation model: **broad utility navigation**.
- Content boundary: Structure and copy shape only. Bring new project nouns, facts, claims, and offers.
- Brand policy: this is not an official guideline, endorsement, or permission to impersonate the reference source.

## Page Blueprint

| Order | Slot | Purpose |
| ---: | --- | --- |
| 1 | `navigation` | Orient the reader before the first claim. |
| 2 | `first_screen` | State the main outcome and give a visible next action. |
| 3 | `participation_path` | Show who joins, what they do, and why they return. |
| 4 | `proof_band` | Make the promise believable without overclaiming. |
| 5 | `detail_sections` | Give deeper readers enough structure to evaluate fit. |
| 6 | `conversion_band` | Repeat the next action after value and proof are established. |
| 7 | `footer` | Close with utility, trust, and legal/support paths. |

## Section Recipes

| Slot | Copy Shape | Agent Rule |
| --- | --- | --- |
| `navigation` | Use short noun-led labels; keep utility paths separate from product paths. | Use navigation categories from the new product, not the reference source. |
| `first_screen` | Specific headline, one compact value sentence, and one or two action CTAs. | Name the new outcome plainly before explaining features. |
| `participation_path` | People-first heading, one behavior sentence, one join action. | Use the new community's real audience and participation model. |
| `proof_band` | Use concrete evidence blocks: metric, customer type, workflow step, or product constraint. | Only include proof that the new project can independently support. |
| `detail_sections` | Alternate short headings with one-paragraph explanations and compact lists. | Split detail by user job, workflow step, or decision criterion. |
| `conversion_band` | Short reminder sentence plus one primary action CTA. | Repeat the real conversion action; do not add urgency unless it is true. |
| `footer` | Grouped utility links with short labels and no marketing prose. | Use owned support, policy, company, and resource links. |

## Rhetorical Pattern

- Opening move: name the reader outcome before listing mechanics.
- Section rhythm: move from value, to proof, to action, then to detail only when needed.
- Proof move: use real product behavior, customer evidence, constraints, or measurable facts.
- CTA move: repeat one primary next action after the reader has enough context.
- Density move: keep compact pages decisive; make dense pages scannable with clear section jobs.

## Agent Instructions

- Use SITE.md for page structure and section order.
- Use VOICE.md for sentence rhythm, CTA shape, and benchmark gates.
- Replace every topic, product noun, market claim, price, and proof point with facts from the new project.
- Do not imply affiliation with, endorsement from, or official representation of the reference source.
- If a needed fact is missing, write a neutral placeholder or remove the claim.

## Content Boundary

- Do not copy source headings, CTA labels, navigation labels, slogans, or campaign names.
- Do not import the reference site's product catalog, audience, pricing, legal claims, or feature names.
- Do not turn structure guidance into a visual design system.
- Do not add urgency, security, performance, customer, or compliance claims without evidence.
